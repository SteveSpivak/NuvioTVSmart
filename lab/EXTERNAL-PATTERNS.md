# External patterns

**Copy the window-and-reuse idea and the request-key idea. Do not import Stremio, Enact, TanStack, Unity, or a WebGL renderer. Lightning is a rewrite, not a patch.**

Provenance: patterns checked against the tree at merge `532d893` (`origin/lab` `deaf7e0` plus row-window `aa86246`). Row-window v1 remains the disabled flag in `js/ui/screens/home/homeRowWindow.js`. Layer-memory reductions from `aa86246` are SYNTHETIC and are not a reason to turn the flag on.

File is 48 lines. https://github.com/Stremio/stremio-web/blob/development/src/common/useVisibleCatalogs.ts                                                                  | Separate "fetch the next catalog" from "mount the row". | TMDB `append_to_response`           | One details call can include videos, images, and credits. https://developer.themoviedb.org/docs/append-to-response                                                                                                                 | Already used. `fetchEnrichment` appends `images,credits,release_dates,content_ratings,videos,external_ids`. Sharing the result between hero and Details is.    | Do not add a second TMDB client.                                                                                                                      |
| Trakt rate limits                   | Authenticated GET: 500 calls / 5 min. Authenticated POST/PUT/DELETE: 1 / s. 429 should honor `Retry-After`. https://developer.trakt.tv/docs/rate-limiting                                                                          | Nuvio already backs off on 429 in `js/core/sync/syncBackoffPolicy.js`. | Unity Addressables                  | `DownloadDependenciesAsync` preloads bundles for a key, and the handle must be released. https://docs.unity3d.com/Packages/com.unity.addressables@1.20/manual/DownloadDependenciesAsync.html                                       | Prefetch the next title's metadata only while focus is stable, and drop it when focus moves. | web.dev long tasks                  | Split main-thread work only after a profile shows the hotspot. See `lab/TRAILER-PIPELINE.md`.                                                                                                            | Do not scrape a media URL or bypass the player.                                                                                                       |

Home already tries to mount one trailer frame.                                                                                                                    | Do not add a second hidden player "to make start faster".                                                                                             |

## Row window, from non-English notes

These do not add a new product. They describe the same fix v1 missed.

- Chinese, Juejin, 2022: a virtual list should update the existing nodes when the start index changes, and skip the DOM write when the index did not change. https://juejin.cn/post/7090119175133200398 The author's "1500–2000 nodes" line is their anecdote, not a Nuvio measurement.
- Japanese, Qiita: the compositor can scroll without the main thread unless a non-passive listener blocks it. Virtual scroll keeps only the visible range. https://qiita.com/nyarlathotep/items/10b0e0ee771054025fb5 Nuvio Home rows move by `translate3d`, not by native scroll, so the compositor-scroll claim does not transfer directly. The visible-range claim does.
- Russian, Purple School: allocate `visible + overscan` nodes once, rewrite their contents, then focus the node that now represents the index. https://purpleschool.ru/knowledge-base/vue/performance/virtual_scrolling This is the v2 hypothesis in `lab/LOADING-ARCHITECTURE.md`.
- German search this session did not return a distinct implementation article. French search returned the LG web-engine overview, not a list algorithm. https://webostv.developer.lge.com/develop/specifications/web-api-and-web-engine Official YouTube parameter pages exist in German, French, Russian, Chinese, and Japanese; they restate the same embed rules, with no extra playback bypass.

## Closed-app notes already in the lab

Netflix TechBlog and BBC TAL were cited from public posts in `lab/RESEARCH.md`. This pass did not re-fetch those articles, so no new claim is added here. Lightning draws with WebGL and does not need HTML or CSS: https://lightningjs.io/docs/#/what-is-lightning/index A port is out of scope.

Chromium's compositing note lists a 3D or perspective transform as a reason for a compositing layer, and says a backing surface per layer can waste VRAM. https://www.chromium.org/developers/design-documents/gpu-accelerated-compositing-in-chrome/ The page is from 2014 and says the stack has changed. It matches the measured unpromote result only as a warning: fewer layers can cost more than they save. Do not treat it as a Chromium 94 trace.
